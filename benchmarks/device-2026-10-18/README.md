# ARMv7 device validation

The scripts run on the actual B8000-H through `user@b8000h`. They are laboratory
tools, not installed product commands. The device keeps a private profile backup
at `~/.local/state/b8k-firefox-validation/profile-before-20261018-194912.tar.gz`.
No user profile, cookie database or credentials are copied into this repository.

`run_device.py` uses Python stdlib and Firefox's built-in
[Marionette protocol](https://firefox-source-docs.mozilla.org/remote/marionette/Protocol.html).
It launches only disposable copied profiles with a loopback control connection
and local deterministic pages. A temporary logind **idle** inhibitor prevents
the screen from going dark during rendering measurements; it is released when
the series finishes. No root access, swap/kernel changes, or system APK updates.

The `installed` variant runs `/usr/lib/firefox/firefox` from the installed 1.3.0
package. Other variants run a private copy of the same Firefox installation,
with only the three b8k preference files relocated from `defaults/pref` to
`browser/defaults/preferences`. The ELF/library contents are copied unchanged.
`runtime-comparison.json` records the reproduced installation defect and the
successful check after relocation. The source fix is in `install.sh`.

Requirements on the device: Firefox 151.0.3, installed b8k-firefox 1.3.0,
mobile-config-firefox 5.4.1, Python 3, b8k-compat, active Wayland session,
the closed user browser, a prepared `calibration-profile`, and 16 deterministic
JPEG files generated by `../local-2026-10-18/prepare_fixtures.py`.

Within the device's laboratory directory:

```sh
python3 check_runtime.py --binary /usr/lib/firefox/firefox
python3 check_runtime.py --binary "$PWD/firefox-app/firefox"
python3 -u run_device.py --variants installed,baseline,factor8,factor16,fps30 --repeats 5
python3 -u run_device.py --variants baseline,inactive30,threshold15,threshold25 --repeats 1 --pressure
```

The first check should fail for the original installed package, the second pass
for the corrected copy. These are actual default/effective branch checks, not
values overlaid by the benchmark. The main series alternates variant order.
Completed runs are skipped on resume; use a fresh results directory to repeat
an entire series. Each run removes only its own disposable HOME on completion.

Main scenario: three different local documents, each with 16 unique-query
1200×900 JPEGs, explicit `img.decode()` completion, 7-second settling, three PSS
samples, 8 seconds of rAF-driven scrolling, 7 seconds settling, native discard
of two background tabs, 7 seconds settling, and first-tab restoration checked
against the correct `?tab=0` URL. The server is loopback-only; HTTP/HTTPS proxy
settings block ordinary external browser requests while exempting loopback.

Pressure scenario: reset tab activity ages, wait 36 seconds, allocate touched
memory until just below the **larger** of the percent and absolute low-memory
thresholds, record tab states without increasing the allocation again, and release.
This is a pressure pulse: memory freed by Firefox/OS can raise MemAvailable
above the threshold during observation; low memory is not maintained. Safety guards
stop below 80 MiB MemAvailable or 30% free swap. Allocator contents are mostly
compressible, so this does not reproduce arbitrary workloads or zram behavior.
Actual ages/thresholds are recorded; do not infer timing from flags alone.

Summarize the collected generated result files on the host:

```sh
python3 benchmarks/device-2026-10-18/summarize_device.py
```

Use `Pss + SwapPss`, not RSS or PSS alone. rAF rates and CPU seconds are neither
physical touchscreen responsiveness nor battery measurements. `passive-session.json`
is the earlier unmodified user-session observation, not the main fixture baseline.
Initial calibration failures are excluded from the comparison.

The first matrix was interrupted by a startup hang, followed by system sleep
and loss of Wi-Fi; the user rebooted the tablet. This does not establish the
cause of the hang. `run_device_main.py` preserves the first harness version;
`run_device_resume.py` preserves the resumed version. `after_main.py` waits
for all 25 successful main results before starting the four pressure screens.
`hold_awake.py` holds an independent idle inhibitor for at most two hours,
and verifies its presence in logind every 30 seconds.

Memory changed across the reboot. For comparisons use `balanced-summary.json`:
three complete rounds (2–4) on the same boot for every main variant. Do not
compare the mixed-boot medians as optimization gains. CPU is normalized by the
actual scrolling interval, with original times retained.

After the serial browser tests, `check_runtime.py --all-defaults` audits every
literal b8k default on the private application. `finish_device.py` compares
the working profile's regular-file contents and symlink targets with its
backup without overwriting later user data, refuses cleanup if any browser or test controller is still running,
removes only private application/profile/run copies, and releases the guard.
The backup and generated results stay on the tablet.
