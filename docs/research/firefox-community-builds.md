# Готовые community-сборки Firefox: что применимо к B8000-H

Проверено 18 октября 2026 года по первичным страницам проектов, сборочным рецептам и GitHub API; дополнительно рассмотрены сообщения авторов собственных тестов. Ничего не установлено. Цель — готовые альтернативы и уже реализованные решения, а не повтор общего списка Firefox prefs.

Короткий результат: оптимизированные сборки существуют, наиболее полезен как инженерный образец **firefox-pure**. Но среди проверенных проектов не найден актуальный готовый Firefox-совместимый пакет **ARMv7 + musl**, с опубликованными воспроизводимыми замерами экономии RAM на сопоставимом 1 ГБ устройстве. ARM64/aarch64 и ARMv7 — разные архитектуры; название «Raspberry Pi» не доказывает ARMv7. Установка glibc/x86 сборки в Alpine не решается переименованием пакета.

Оценки доказательности: **A** — воспроизводимые измерения на сопоставимом устройстве; **B** — проверенные исходники/пакеты, реализованный механизм; **C** — отдельные firsthand-тесты с существенными ограничениями; **D** — заявление/маркетинг без достаточно описанного теста. У проектов ниже есть B для существования механизма/релиза; A для экономии RAM на нашем планшете не найдено. Наличие готового бинарника и доказательство его эффективности — разные утверждения.

## Сравнение кандидатов

| Проект | Что уже реализовано | Готовый ARMv7 musl | Оценка для этого проекта |
|---|---|---|---|
| CachyOS firefox-pure | PGO, cross-language full LTO, O3, системные библиотеки, сокращённые функции | В проверенном рецепте нет: x86_64/glibc | Лучший донор сборочного конвейера, не устанавливаемая замена |
| Mercury | CPU-варианты x86, ARM64, оптимизации и патчи других форков | В latest assets нет | Последний опубликованный релиз старый; готовую сборку исключить |
| LibreWolf | Актуальный privacy-форк, поддерживаемый набор defaults/патчей | Не подтверждён; официальные ARM-инструкции относятся к ARM64 | Донор отдельных настроек, не доказанное средство уменьшения RAM |
| Floorp | UI для управления вкладками/исключениями сна | В latest Linux assets нет: x86_64/aarch64 | Переносить идею unload в Firefox проще, чем портировать весь форк |
| Waterfox | Поддерживаемый Firefox-форк, x64/ARM64 Linux пакеты | В downloads нет | Не подтверждён выигрывающий low-RAM вариант |
| Tete / SkyKakapo | CSIR PGO, опциональный тестовый mimalloc | Нет: Windows x64 SSE3 | Интересен метод обучения PGO, не бинарник для Alpine |
| Pale Moon | Независимый UXP/Goanna, исторический ARMv7 порт | Только найден старый архив Pi 26.1; актуальный musl-пакет не подтверждён | Другая совместимость; не готовый современный Firefox substitute |

## 1. firefox-pure и история Cachy Browser

Первичный [PKGBUILD ventureoo](https://github.com/ventureoo/PKGBUILDs/blob/a9332610393b99498de104d487c87b78887b9381/firefox-pure/PKGBUILD) на момент проверки задаёт Firefox 158.0, `arch=(x86_64)` и glibc; PGO, `--enable-lto=cross,full`, C/C++ O3, Rust opt-level 3, Wayland-only toolkit, jemalloc, Gentoo patches. Убираются accessibility/webdriver/negotiateauth/speechd/necko-wifi и некоторые служебные функции. PGO запускается через headless cage/pixman. Это конкретная рабочая инженерная идея для software-rendering окружения, хотя работа на ARMv7 не проверена. Строки конфигурации подтверждают намерение, а не отдельный количественный эффект каждой опции.

[Официальный CachyOS announcement](https://blog.cachyos.org/blog/2507-july-release/) сообщает, что cachy-browser прекращён, взамен доступны firefox-pure и cachyos-firefox-settings поверх обычного Firefox. Не стоит рекомендовать старый Cachy Browser или архивный CachyOS-Browser-Settings как действующий основной продукт. [Карточка пакета](https://packages.cachyos.org/package/cachyos/x86_64/firefox-pure) подтверждает готовую x86_64/glibc поставку; версия карточки может отставать от рецепта. Здесь проверены рецепт и факт поставки, установка/исполнение не проводились.

[Firsthand-тест CachyOS Forum, 11 мая 2026](https://discuss.cachyos.org/t/how-to-install-hellfire-browser/29459/13) сравнивает firefox-pure с Brave/Chromium/Hellfire. Автор фиксировал частоты, но запускал четыре браузера одновременно, использовал неодинаковые расширения и сообщает, что только Speedometer был устойчивым. Обычного Firefox как отдельного baseline нет. Это **C**, не доказательство выигрыша firefox-pure над стандартным Firefox и не RAM-бенчмарк ARM. Полезный следующий шаг — перенос небольшого проверяемого набора build-идей в Alpine APKBUILD, по одному фактору, без слепого копирования всех отключённых возможностей.

## 2. Mercury

[Проект](https://github.com/Alex313031/Mercury) предлагает оптимизации компилятора и патчи LibreWolf/Waterfox/Ghostery/Betterfox. GitHub API latest на дату исследования возвращает [129.0.2, опубликованный 17 сентября 2024](https://github.com/Alex313031/Mercury/releases/tag/v.129.0.2). В assets есть Linux SSE3/SSE4/AVX/AVX2 и ARM64, но не ARMv7/musl. Последний push репозитория не равен новому защищённому релизу. Заголовок релиза «Raspi» относится к имеющемуся ARM64 asset; перенос на 32-битный B8000-H из этого не следует. Для обычного доступа в интернет старую готовую сборку не выбирать.

Есть [собственные измерения пользователя на Ryzen 9950X](https://www.reddit.com/r/browsers/comments/1fkr4i2/mercury_finally_updated_v12902/): Mercury AVX2 129.0.2 получил Speedometer 19.7, Firefox Nightly — 22.9. Это не корректный контролируемый A/B: разные версии, чистый профиль Mercury против ежедневного Nightly с дополнениями/другими вкладками; точная версия теста не закреплена. Однако даже такой отчёт не подтверждает универсальное рекламное «быстрее Firefox». Оценка **C**, перенос цифр на ARMv7 и RAM недопустим.

## 3. LibreWolf

[Описание проекта](https://librewolf.net/) называет целью privacy/security/freedom, а не минимальную память. [FAQ](https://librewolf.net/docs/faq/) говорит о поддержке ARM64/aarch64 и предупреждает, что отключение JIT замедляет сайты и лишает WebAssembly. [Официальный apt index](https://repo.librewolf.net/dists/librewolf/main/) показывает amd64 и arm64; ARMv7 APK не подтверждён. «ARM supported» из FAQ нельзя читать как совместимость с Cortex-A7.

[Страница тестирования LibreWolf](https://librewolf.net/docs/testing/) перечисляет Speedometer/JetStream и другие инструменты, но не публикует там воспроизводимую сравнительную RAM-серию на 1 ГБ ARMv7. Поэтому privacy-патчи можно изучать, а готовую экономию памяти обещать нельзя. Anti-fingerprinting, ограничения WebGL/доступности сайтов и иной профиль могут изменить результаты в обе стороны. Доказательство работающего проекта — **B**, целевого low-RAM выигрыша — не найдено.

## 4. Floorp

[Floorp 12.20.2 от 17 октября 2026](https://github.com/Floorp-Projects/Floorp/releases/tag/v12.20.2) содержит Linux x86_64 и aarch64 tarballs; ARMv7 отсутствует. [README](https://github.com/Floorp-Projects/Floorp) также перечисляет Linux x86_64/AArch64. Это актуальный выпускаемый форк, не облегчённая ARMv7 сборка.

[Текущая документация Tab Sleep Exception](https://docs.floorp.app/docs/features/tab-customization/) прямо описывает native Firefox auto-unload при недостатке RAM, к которому Floorp добавляет исключения сайтов. Старые обсуждения «sleeping tabs» могут описывать другие версии. Наличие UI сна не доказывает меньшую память активной одной страницы или более лёгкий engine. На нашем планшете полезнее проверить штатную выгрузку и защитить аудио/формы от нежелательного сброса. Доказательность механизма **B**, сравнительного целевого эффекта нет.

## 5. Waterfox

[Официальные downloads](https://www.waterfox.com/download/) на дату проверки предлагают 6.7.6 от 13 октября 2026, Linux x64 и ARM64 DEB/RPM/tarball. Linux требования указывают glibc; готовый ARMv7/musl пакет не представлен. То, что пакет ARM64 существует, не позволяет запустить его на 32-битном SoC. Проект действует, но найденные первичные сведения не содержат контролируемого измерения RAM на нашем классе железа. Рассматривать его как готовую low-RAM замену оснований нет; **B** для поставки, не A для эффективности.

## 6. Tete private builds → SkyKakapo

Актуальный [сайт автора](https://tete009.pages.dev/en-US/software) сообщает о преемнике SkyKakapo 158.0 от 13 октября 2026: Windows x64 SSE3, CSIR PGO с профилированием обычного browsing; патчи включены в Source folder. Старые Firefox Private Builds прекращены на серии 153. В 158.0 предлагается экспериментальный переключатель mozjemalloc→mimalloc через `TT_ENABLE_MIMALLOC=1`. Это реальный пример оптимизированного downstream, а не прекращённый проект.

Но нет Linux ARMv7/musl поставки и опубликованной на этой странице воспроизводимой low-RAM серии. Польза — изучить PGO workload и точечные патчи; Windows DLL/tmemutil и allocator toggle не являются переносимым решением Alpine. Оценка **B** для реализованного механизма, **D** для неподкреплённого количественно обещания эффективности.

## 7. Pale Moon и исторический pcxFirefox

[Архив Pale Moon Pi](https://archive.palemoon.org/contrib/dimag0g/) действительно описывает ARMv7 и личное тестирование автором на Banana Pro. Однако это **Pale Moon 26.1**, не актуальный security-maintained пакет. Приведённые советы Flash/Gnash дополнительно показывают исторический характер страницы. [Современные requirements](https://www.palemoon.org/systemrequirements.shtml) требуют минимум 2 ГБ свободной RAM для официальных сборок; Linux 32-bit binaries прекращены. [Техническое описание](https://www.palemoon.org/technical.shtml) объясняет независимый Goanna/UXP fork, поэтому привычная совместимость сайтов/Firefox WebExtensions не гарантируется. Если исследовать — как отдельный браузер для фиксированного набора сайтов, не переносимый профиль Firefox. Готовая поддерживаемая ARMv7 musl замена не установлена.

[pcxFirefox SourceForge](https://sourceforge.net/projects/pcxfirefox/files/) показывает latest Firefox 53.0.3 VC2015 x86 SSE2 betterpgo, датируемый 2017 годом; [исходный репозиторий](https://github.com/xunxun1982/pcxfirefox) последний push имел в 2016. Это Windows-проект, исторический пример mini-edition/PGO, не кандидат для установки сейчас. Ни старый номер версии, ни исчезновение функций не обеспечивают безопасный современный web.

## Как использовать найденное

Для B8000-H разумно заимствовать **рецепт**, а не менять платформу ради чужого бинарника: текущий Alpine Firefox + адресно перенесённые build-идеи firefox-pure; пример представительного PGO у Tete; штатная выгрузка вкладок вместо переноса целого Floorp. Сначала сверять код с выбранной версией Gecko, musl-патчами и измерениями на устройстве. Ни один найденный проект не устраняет 1 ГБ физической памяти и software video decode.

Проверенные community-материалы подтверждают, что сборочные оптимизации применяют на практике. Они **не подтверждают**, что какой-либо из этих форков уже доказанно уменьшит RAM нашего планшета на заданный процент. Для перехода к готовому продукту нужны одновременно актуальные security updates, совпадающие ARMv7/musl ABI, совместимые сайты/расширения и собственный PSS+swap A/B. Пока этих четырёх условий нет, поддерживаемая пакетная база с небольшим переносимым набором изменений имеет лучшую проверяемость.
